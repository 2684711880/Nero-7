# Joy-Con 夹爪修复与 IMU 使用分析（2026-10-30）

## 已完成的夹爪修复

旧逻辑依赖反馈开度与50 mm阈值切换目标，并在反馈大于100 mm时抛异常。实际运行日志可见右夹爪连续多次发送闭合目标；这是按键意图被反馈状态替代的缺陷，不是二态切换。

现在每侧独立记忆“最后一次发送的目标”，第一次按下闭合，之后张开/闭合交替；仅发送0或0.1 m，力仍为1 N。启动不自动开合，长按不重复触发。开度反馈不决定下一次按键动作。目标值沿用官方wrapper `open()`/`close()` 默认值。

隔离ROS回归先在旧实现复现“120 mm反馈触发异常”，修复后验证恒定120 mm反馈也能输出左侧0/100/0 mm、右侧0 mm；重复按下事件（没有释放）不重复切换。官方回调测试验证只控制夹爪，不调用机械臂 `move_j`/`move_js`。尚未进行本次修改后的真机开合验证。

## 已有证据

| 项目 | 已验证的事实 | 对使用的影响 |
| --- | --- | --- |
| IMU输入 | 当前只积分陀螺仪；不使用加速度计校正，也没有绝对航向来源 | 偏置和丢失运动会逐渐改变中立姿态；加速度计只能帮助倾角，不能单独解决yaw漂移 |
| 数据间隔 | 90秒原始采样中两侧最长间隔约0.73秒；代码对大于30 ms间隔跳过积分 | 丢包期间手部运动无法恢复，之后“同一手持姿态”不一定对应原来的目标 |
| 小角速度 | 每轴小于1°/s直接置零 | 极慢转动可能没有响应，三个轴各自过门限会产生手感不一致 |
| 输出速率 | 50 Hz、相对目标每帧最多1° | 快速手部转动会受目标步长限制；不能把100%固件速度等同于姿态无限快跟随 |
| 姿态范围 | 当前90°合成旋转硬上限，已替换原20°限制 | 相对桌面平放朝向拿起手柄也会消耗偏转额度 |
| 官方接口 | ROS将四元数转换为XYZ欧拉角，SDK `move_p` 发出笛卡尔目标，公开调用没有关节种子参数 | 笛卡尔小步长不保证七轴IK支路连续 |

原始采样与回放在 `hardware_ws/validation/joycon_timing/imu_mapping_current/`；历史采样的20°限幅是旧版本行为。

## 当前准备姿态接近欧拉角奇异位置

根据实际记录的关节角与工程模型，准备姿态在左右单臂基座坐标系的pitch均约−88.29°，距−90°仅约1.71°。

沿该位置附近构造连续四元数轨迹，并调用实际 `AgxArmRosNode._create_pose_cmd`：每帧空间旋转仅0.1°，转换后的某个RPY分量跨边界时会变化180°。复现结果在 `euler_boundary.json`/`euler_boundary.csv`。

这是欧拉角等价表示切换，不能据此认定真实机械臂转动180°或证明固件IK切换。它表明仅看RPY数值或只滤波欧拉角会误判；是否与用户观察的“抽一下”对应，需要同一时刻的目标四元数、实际发出的RPY及七轴反馈联合验证。当前运行日志没有这些完整同步数据，不能把该次物理抽动定因。

## 优化顺序

1. **持握姿态重新对齐。** 将静止偏置校准与操作中立姿态分开：先估计偏置，再在实际持握姿态记录参考。重新对齐时同时更新手柄参考与对应机械臂姿态锚点，保持当前目标连续；不靠长期持握接近90°上限进行操作。
2. **在四元数域处理手感。** 轻量平滑姿态/角速度，按实际dt限制目标角速度和角加速度；调整小角速度死区，避免极慢动作被硬置零。需要用已有记录回放比较延迟与抖动，不盲目加重滤波。
3. **增加倾角约束。** 融合陀螺仪与加速度计，利用静止/低动态时的重力方向抑制roll/pitch漂移；动态加速度期间降低重力校正权重。yaw仍需要重对齐或外部参考。
4. **单独排查关节抽动。** 下一次记录目标四元数、官方转换后RPY、实际关节角/速度、IMU事件间隔及模式切换时间。区分输入姿态跳变、欧拉表示跨边界、固件IK支路切换和停止/重启模式；不能用姿态低通宣称解决IK多解。

保持100%官方速度设置和90°软件上限；本次未改变IMU算法、关节IK路径或准备姿态。

精简发布证据见[验证目录](validation/joycon/20261030/README.md)。完整原始CSV与运行日志保留在采集机器，不随仓库上传。

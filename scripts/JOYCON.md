# 双臂 Joy-Con 遥操作

面向 Ubuntu 22.04 / ROS 2 Humble、NERO 固件1.21及两只蓝牙Joy-Con。以下命令均在仓库根目录执行；也可把脚本改为你的完整路径。`bash scripts/joycon.sh`只是预览，`--execute`和`--return`会移动机械臂。

## 环境准备

```bash
git submodule update --init --recursive
bash scripts/build_official_control.sh
```

安装 [JoyCon Robotics](https://github.com/box2ai-robotics/joycon-robotics) 所需的Linux `hid-nintendo`/`joycond`、输入设备权限配置，将左右手柄蓝牙连接并组合。当前主程序直接读取Linux输入事件，不依赖该项目的Python运动映射。准备姿态采集复用项目的只读CAN工具，需要系统OpenCV（Ubuntu可用`sudo apt install python3-opencv`）。

设备约定：左臂`can1`、右臂`can0`，CAN 1 Mbit/s。请按设备实际接线核对；这两个名字不能自行证明左右身份。姿态文件`config/joycon/ready_pose.json`记录的是本工程这台机器人，包含左臂实测和右臂镜像来源；换机器人或安装状态后应重新记录，而不是直接执行仓库中的角度。

## 手动操作

一键启动（会运动）：

```bash
bash scripts/joycon.sh --execute
```

启动前将手柄平放静止，按键朝上、肩键朝整机 X+。手臂准备动作结束后会自动校准 IMU；等终端显示“控制门开启”和两侧“输入已回中”后再拿起操作。

启动顺序：官方 SDK 以 10% 速度准备双臂 → 关节误差在 0.5° 内持续 0.5 秒 → 启动两侧官方驱动，`speed_percent=100`、反馈 200 Hz → 校准手柄 → 50 Hz 遥操作。退出用 Ctrl+C。

准备姿态由人工摆放后采集的真机关节反馈定义，保存在 `config/joycon/ready_pose.json`。启动和归位读取同一份记录，不使用固定的 90° 关节预设。

首次使用或更新姿态：按当前手动示教方式摆好两臂，保持稳定，再执行：

```bash
bash scripts/joycon.sh --record
```

也可以分别摆放、分别记录，另一侧已有记录会保留：

```bash
bash scripts/joycon.sh --record --arm left
bash scripts/joycon.sh --record --arm right
```

仅记录一侧时可以保存，但两侧均有有效记录前，双臂启动和归位会拒绝执行。没有摆好的手臂不要记录。

如采用左臂实测、右臂镜像，在记录左臂后执行：

```bash
bash scripts/joycon.sh --mirror-left-to-right
```

该命令只更新文件，不驱动右臂。工程模型的镜像关节符号为 `[-,+,-,+,-,-,+]`，并校验关于整机 Y=0 平面的法兰位置和姿态镜像以及目标关节限位。右臂记录注明 `urdf_mirror_of_left` 和 `hardware_verified=false`，表示目标来自模型镜像，尚未真机到位验证。后续重新记录左臂时，如需继续镜像，应再次运行此命令更新右臂。

采集直接接收 CAN 反馈，不调用使能或运动接口，也不改变控制模式。需要机械臂控制器保持上电并输出反馈。记录包含左右 CAN 映射、七轴弧度、角度、采样时间和稳定性；所选手臂必须都有新鲜、稳定的完整七轴反馈才会保存。已有记录会先备份再更新。未记录时启动和归位均拒绝执行，不回退到手写目标。

启动使用官方 `move_j` 以 10% 速度从当前反馈位置到记录姿态；已到位的手臂不重复动作。目标限位已按工程模型检查，此流程未做环境碰撞规划。

仅预览关节目标和模型方向，不连接 CAN：

```bash
bash scripts/joycon.sh
```

100% 是官方固件速度比例，不等于末端恒速或关节加速度缩放；启动流程未更改固件关节速度、加速度上限。遥操作保留 1.25 rad/s 实测速度退出保护、反馈新鲜度检查、真实 IMU 事件 2 秒超时保护。当前仍为官方 `move_p`，没有新增 IK 求解。

映射：摇杆前后左右，L/R 上升，摇杆按压下降，ZL/ZR 夹爪，Capture/Home 回启动位置（只恢复位置）；无保持键。

夹爪仅有两个目标：完全闭合0 m、完全张开0.1 m（官方wrapper `open()` 默认值）。各手柄对应侧的ZL/ZR每次有效按下交替切换，按住不重复；每次启动后的首次按下明确请求闭合，之后张开、闭合交替。以最后发送的目标记忆状态，不再用实际开度或50 mm阈值判断；启动时不自动开合。命令只含`gripper`，力参数保留1 N；“完全闭合”指目标0，不代表夹持物体时实际能到零。

## 停止与完整归位

先在遥操作终端按 `Ctrl+C`，等待两侧关闭控制门、驱动退出。也可以在另一个终端显式停止，兼容独立启动的遥操作或残留的本工程官方驱动：

```bash
bash scripts/joycon.sh --stop
```

看到“已退出，可以手动执行 --return”或“当前没有…”后，再执行归位：

```bash
bash scripts/joycon.sh --return
```

此命令不读取手柄或 IMU，使用官方 SDK `move_j`，以 10% 速度回到记录文件中的完整关节准备姿态。只控制七轴，保留夹爪开度。各轴误差 ≤0.5° 持续 0.5 秒后才报告成功。若已有控制进程、关节反馈过期、当前角度超官方限位或到位超时，会拒绝或中止；运动阶段中止时尝试请求保持当前反馈角度。

归位前、到位确认及异常保持均读取完整四帧拼出的新鲜七轴CAN反馈，避免SDK刚启动时未收齐的轴暂为0。当前角度和目标角度按官方SDK精确NERO限位检查；例如J6约为[−42°,55°]，不使用URDF取整后的[−41.826°,54.431°]作为真机边界。真正超出官方范围仍拒绝运动。

启动器会在 Ctrl+C 时先请求遥操作清理，再退出本次创建的完整驱动进程组；无响应的子进程会经过限时退出和最终清理，避免只退出 launch 后留下占用 CAN 的驱动。`--stop` 按完整脚本路径和驱动命名空间识别本工程进程，不广泛结束所有Python/ROS任务。归位命令不会跳过独占检查，也不会自行停止控制进程。

完整归位从当前关节位置直接进行关节空间运动，不沿原路返回，也未做碰撞规划。它用于反馈正常、路径空间明确的恢复，不是急停；若存在碰撞或夹持，应先处理障碍，不能靠归位指令保证恢复。Ctrl+C 是软件停止请求，不能替代硬件急停。

Capture/Home 仅恢复启动 XYZ，保留当前姿态；需要恢复七轴姿态时使用 `--return`。归位后重新执行 `--execute` 会识别已到准备姿态，再开始手柄校准。

## IMU 旋转诊断

当前姿态映射取消原20°限制，以90°作为相对校准朝向的合成旋转软件硬上限；每次目标步长仍限1°，发送频率50 Hz。90°以内保持输入姿态，不做额外幅值压缩；多个轴共享合成转角上限。90°是软件配置，不是所有末端位置均安全可达的保证，关节限位和实测速度保护继续生效。

修改前，2026-10-30 的90秒只读采样发现，两侧积分相对角度峰值约131°，映射目标仍限制在20°；左、右样本触及限幅的比例约74.5%、71.5%。存在约0.73秒的数据间隔，积分结果不是外部测量的真实姿态；该采样没有驱动机械臂旋转；随后按用户要求把旋转上限设为90°、驱动速度设为100%。

原始内核陀螺仪计数、角速度、事件时间、积分姿态及限幅输出保存在 `hardware_ws/validation/joycon_timing/imu_mapping_current/gyro_mapping.csv`。这里的“原始”指 Linux 输入事件里的陀螺仪数据（驱动已做出厂标定与左右轴对齐），不是芯片寄存器数据；加速度计没有参与当前姿态积分。

## 不连接CAN的回归测试

构建并准备官方环境后执行：

```bash
bash scripts/test_joycon.sh
```

测试包含姿态映射、夹爪二态切换、精确关节限位、完整反馈、独立进程清理，以及隔离ROS域103/104中的模拟驱动。不会读取手柄、连接CAN、使能或移动机械臂。运行时需要域103/104没有其他任务。

`scripts/tests/joycon_live_mock_capture.py`是额外的真实手柄+模拟驱动工具，必须显式使用域105并按提示校准，**不会由上述回归脚本运行**。`joycon_readonly.py`、`joycon_diagnose_capture.py`与`joycon_imu_mapping_capture.py`用于输入和IMU只读诊断。

验证证据见[发布验证目录](../docs/validation/joycon/20261030/README.md)，IMU与关节抽动的已知问题见[分析记录](../docs/joycon_imu_analysis.md)。本项目仍使用官方固件`move_p`，不提供碰撞规划或上一帧关节角作为IK种子；用户已反馈偶发关节抽动，尚未完成根因定位。当前安全检查不能作为全工作空间安全性保证。
